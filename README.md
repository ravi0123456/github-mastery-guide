# GitHub Mastery Guide

Welcome, **Ravi** (`ravi0123456`)!

This repository is your complete, self-paced path from **GitHub beginner** to **office-ready professional**. Everything you need is written here. Work at your own speed, tick the checklist as you go, and message your assistant with screenshots whenever you get stuck.

**Practice repo:** [hello-world](https://github.com/ravi0123456/hello-world) — use this for almost every hands-on task.

---

## How to use this guide

1. Read one chapter at a time (suggested order below).
2. Do every **Practice** task yourself on GitHub or in VS Code.
3. When a screen does not match the guide, take a screenshot and ask your assistant.
4. Tick the progress checklist on this page as you finish each stage.
5. Keep `glossary.md` open in another tab — it explains every new word in one line.

You do **not** need to finish everything in one day. Steady practice beats rushing.

If you are an IDMC admin and Git is new, start with chapter 00, then 06, then 07.

## Progress checklist

### From zero
- [ ] I can say Git is the history tool and GitHub.com is only one website that hosts it
- [ ] I know YAML is a settings form, not a program
- [ ] I know Groovy is the Jenkins recipe I should not edit on day one
- [ ] I know a commit of `flo_dev.yml` is what starts the deploy robot

### Foundations
- [ ] I can open my GitHub profile and find my repos
- [ ] I understand Public vs Private
- [ ] I edited a file on github.com and created a commit
- [ ] I know what `main` means
- [ ] I completed Practice tasks on [hello-world](https://github.com/ravi0123456/hello-world)

### Daily workflow
- [ ] Git is installed on my Windows 11 PC
- [ ] I cloned a repo into VS Code
- [ ] I can run status, add, commit, push
- [ ] I created a branch and opened a Pull Request
- [ ] I know why we do not commit secrets

### Office and team
- [ ] I created an Issue with a clear title
- [ ] I opened a PR and asked for review
- [ ] I know merge vs conflict at a basic level
- [ ] I understand collaborators vs organizations

### Pro tools and habits
- [ ] I know what GitHub Actions / CI means
- [ ] 2FA is on (or I have a plan to enable it)
- [ ] I can follow the office playbook for a new feature

### IDMC at work
- [ ] I can point to the on-prem repo URL and the YAML file that starts a deploy
- [ ] I know source control in IDMC is not the same as the Jenkins deploy path
- [ ] I know why PROD can have no source-control settings
- [ ] I have a named test tag ready before I commit `flo_dev.yml`
